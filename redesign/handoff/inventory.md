# Capability inventory

What people need to be able to do. Each need is a job story with an ID. The groups follow the jobs people do, not any existing layout. Nothing here prescribes how anything looks, where it sits or what it is called.

**Who:** a small sales-and-operations team at one company. Everyone uses the same shared data. There is no sign-in and nobody has a different level of access.

---

## Shape the work (W)

- **W1** When something needs doing, I want to capture it in a sentence and save it in seconds, so that it isn't forgotten while I'm busy.
- **W2** When I capture a task, I want to optionally say what kind of task it is (task type), how I'm in touch (touch point: call, email, meeting…), how important it is (priority: high, medium, low), when it starts and when it is due (start date, end date as the deadline), when the last action was taken, and the key points, so that anyone can pick it up without asking me.
- **W3** When I capture a task, I want to name one or more responsible persons and any number of informed persons, each informed person with an optional short note on their part (for example "backup" or "recipient"), so that ownership and who to keep updated are explicit.
- **W4** When I type a person's name, I want to be offered the names already in use, and still be able to add a new one, so that the same person isn't spelled three ways.
- **W5** When a task is finished, I want to mark it done in one action from wherever I see it, so that the active work stays short and honest.
- **W6** When I look back, I want to look back at finished tasks (and know how many there are) and then set them aside again, so that I can check what was done without cluttering daily work.
- **W7** When a task changes, I want to edit any of its details or delete it (with a confirmation), so that the plan stays accurate.
- **W8** When there is a lot of internal work, I want to organise tasks that aren't about a specific company into named task groups, so that related work stays together.
- **W9** When some task groups matter most, I want to mark them as important and have them come before the others, so that I see them before anything else.
- **W10** When I work on one task group, I want to concentrate on one group at a time, set the others aside, and know how many tasks each holds, so that I can concentrate.
- **W11** When a task group is no longer needed, I want to create, delete and reassign task groups freely, and when I delete one its tasks should become ungrouped rather than disappear, so that no work is lost.
- **W12** When I work on tasks, I want them told apart automatically as three kinds: internal work, work for prospects, and work for existing clients, so that sales follow-ups aren't buried under internal work. A task tied to a company counts as client work once that company's deal is done, and as prospect work before that.
- **W13** When I scan tasks tied to companies, I want to know at a glance the company, how many days remain until the deadline or how overdue it is, and how many days have passed since the last action, with urgency made obvious, so that I know which ones are slipping.
- **W14** When I scan tasks tied to companies, I want to filter them by task type and by "no action for at least N days", and sort by company, description, task type, deadline or last action, so that I can work through the ones that need me. Prospect work should by default come with the latest deadlines first and undated tasks last.
- **W15** When I scan tasks, I want to choose which details I see and how much of each is visible, and have that remembered on my device, so that it fits how I work.

## Know what's due and who's on it (D)

- **D1** When I plan, I want to see how every task spans time from its start date to its deadline, with who is responsible recognisable at a glance and today easy to locate, so that I can spot overlaps, gaps and crunches.
- **D2** When I plan across time, I want to limit what I see to one task group, ungrouped work, prospect work or client work, so that each conversation stays focused.
- **D3** When a task has no dates, I want it to still show up, clearly marked as undated, so that it doesn't silently fall out of the plan.
- **D4** When I start a day, I want to see everything happening on a given date, whether it starts, ends, runs through or is a single-day task, with responsible and informed persons and key points, so that I know what today involves.
- **D5** When I look at a day, I want to move to the previous or next day, to any date I choose, or to today; and the first time I look, I want to land on today if something is happening, otherwise on the next date that has something, so that I never start on an empty day.
- **D6** When I check one person's load, I want to pick a person and see which tasks they own and which they're only kept informed on (with their note), and how many of each, so that I can balance work and know who to update.
- **D7** When I plan a month, I want to see tasks and the team's external meetings and events together across a month, with today easy to find, so that deadlines don't collide with meetings.
- **D8** When a month is busy, I want to choose whether tasks, external events or both are shown, still tell when a day holds more than fits, and see everything on any day I choose, so that it stays readable.
- **D9** When I see an external event, I want its start time (or that it lasts all day) and a way to open it in the outside scheduling service, so that I can get details there. External events can't be changed from here.
- **D10** When the outside scheduling service isn't set up or fails, I want a short notice saying so, while tasks still work, so that I know why events are missing.
- **D11** From any of these ways of looking at work, I want to open a task and edit it, mark it done or delete it, so that I never have to go elsewhere to fix something I spotted.

## Win new business (B)

- **B1** When I meet a potential client, I want to record who they are (company, contact person, whether it's a client, a partner or an individual partner, its industry, how we found it), where we stand (status, the products it's interested in, priority) and what is happening (the date of the last action, the next actions and the target date for the next action), so that the whole team knows where we stand. Only the company name is required.
- **B2** When I go through prospects, I want to tell them apart from companies whose deal is done, from companies we haven't contacted yet, and from companies that are on hold or rejected, and know how many each group holds, so that each kind of work has its own focus.
- **B3** When a company is not yet contacted, I want to record it with its type, planned outreach date, priority, industry, how we found it and notes, so that I can build a backlog of leads to approach.
- **B4** When a company says no or not now, I want to record it with its type, the product offered and the reason for rejection or hold, so that we learn from it and can revisit it later.
- **B5** When a company moves on (for example from not yet contacted to active, or from active to on hold), I want to move it to its new group and fill in what that group needs, with what I already know carried over, so that I don't retype anything.
- **B6** When I check prospects, I want a quick summary of how many there are, how many are high priority, how many are waiting for a follow-up, and how many have had no contact for 14 days or more ("going cold"), so that I know where to act.
- **B7** When I scan companies, I want to see how many days ago the last action was and whether the target date is close (within 3 days) or missed, highlighted by urgency, so that nothing slips.
- **B8** When I'm looking for a company, I want to search by company, contact person, source or product (or by industry and notes for leads, or by reason for on-hold ones), and filter by status, product and priority, so that I find it fast.
- **B9** When I scan companies, I want to sort by any detail (company, last action, status, priority, target date, planned outreach…) and reverse the order, so that I can see them in the order that suits the moment. By default the most recent action comes first.
- **B10** When a detail changes, I want to update a single detail of a company (a status, a date, a note) in one quick step, without going through its whole record, so that keeping things current is effortless.
- **B11** When I need to act on a company, I want to create a follow-up task for it straight away, pre-filled with the company, the follow-up task type and its target and last action dates, then see a short confirmation, so that sales actions land in the team's task work.
- **B12** When a company's last action date or target date changes, I want its linked tasks to update to match, and when I update those dates on a linked task, I want the company to update too, so that the two never disagree.
- **B13** When I open a task tied to a company, I want to jump straight to that company's full record, so that I have its context.
- **B14** When a company drops out entirely, I want to delete it with a confirmation, so that the records stay clean.

## Understand each prospect (U)

- **U1** When I qualify a prospect, I want to write structured notes under fixed headings: client need, current situation, pain and business impact, solution fit, urgency and timing, stakeholders and decision process, commercial readiness, next step and ownership, potential blockers, so that every opportunity is assessed the same way.
- **U2** When I qualify a prospect, I want to rate how likely the opportunity is (very high, high, medium, moderately low, low), so that the team can compare opportunities at a glance.
- **U3** When I have a lot to say about a prospect, I want room for long free-form remarks (history, concerns, context) without them crowding what I see when I look across all prospects, so that one prospect's detail doesn't get in the way of seeing all prospects at once.
- **U4** When I'm writing notes, I want them saved automatically as soon as I move on, with a quiet sign that it's saving, so that I never lose words and never have to remember to save.
- **U5** When I start qualifying a company we're already tracking, I want to open its qualification notes from the company record in one action (creating them if they don't exist yet) and go back to the company record from the notes, so that the two always stay connected. Each tracked company has at most one set of notes.
- **U6** When I add notes for a prospect that isn't tracked yet, I want to create them on their own and later link them to a tracked company, so that early conversations aren't blocked by data entry.
- **U7** When I compare prospects, I want to compare all prospects' answers to the same heading together, search across everything written, and see how many prospects there are, so that patterns stand out.
- **U8** When a prospect is no longer relevant, I want to delete its notes with a confirmation, so that the set stays focused.

## Keep the record of past clients (R)

- **R1** When we finish work with a client, I want to add it to a long-term record of every company we've served, with its sector, so that we can say who we've worked with.
- **R2** When a client is a group of companies, I want to add its subsidiaries under it, move a subsidiary to a different parent company, and rename or delete either, so that the structure matches reality.
- **R3** When a parent company is only an umbrella, I want to keep it on record without counting it in the totals, while its subsidiaries still count, so that the number of clients we claim is accurate.
- **R4** When I report on our track record, I want to see the total number of clients, how many parent companies are counted and not counted, and how many subsidiaries there are, so that I can quote figures with confidence.
- **R5** When I report by sector, I want a breakdown of how many counted companies (parents plus their subsidiaries) fall in each sector, largest first, with each one's share of the total and a figure for those with no sector, adding up to the same total, so that I can show where our experience lies.
- **R6** When I type a sector, I want to be offered existing sectors and have different spellings ("retail", " Retail ") treated as the same sector, so that the breakdown isn't split by typos.
- **R7** When the record is long, I want to search across parent companies, subsidiaries and sectors (showing matching subsidiaries under their parent), show or hide the subsidiaries under each parent company, one at a time or all together, and sort by name, sector, whether counted or number of subsidiaries, so that I can find and check anything.
- **R8** When I delete a parent company that still has subsidiaries, I want to be told to move or delete them first, so that no subsidiary is orphaned.
- **R9** When saving fails, I want a short message asking me to try again, so that I know it didn't go through.

## Document how work moves (M)

- **M1** When a recurring process involves several people, I want to write it down as a flow: a name, a description and ordered flow steps, so that everyone follows the same process.
- **M2** When I describe a flow step, I want to give it a title, a description and any number of roles, each role with a label (for example responsible, informed, consulted) and the names of people in it, and reorder the roles, so that each step's ownership is clear.
- **M3** When a process reaches a decision, I want to add one decision to a flow, with several outcomes, each marked good or bad, with its own title, description and roles, and optionally pointing back to an earlier flow step to repeat from, so that loops and exceptions are documented.
- **M4** When I maintain flows, I want to keep several flows, move between them, create new ones, rename them, edit any part where I read it, add or remove flow steps, outcomes or the decision, and delete a flow with a confirmation, so that the documentation keeps up with how we actually work. Changes save instantly.

## Tailor the data (C)

- **C1** When the team tracks something new about companies, I want to add my own fields to each group of companies (short text, long text, number, date, or a choice from options), so that the record keeps pace with our process.
- **C2** When fields multiply, I want to choose which fields are shown, rename them and decide how much of each is visible, per group of companies, and remove fields I added (the stored data stays), so that each group shows only what matters.
- **C3** When the options for a choice change (status, type, priority, or my own choice fields), I want to add options with a colour, rename them (and have every company using the old name follow), remove them, or clear a company's choice, so that the vocabulary evolves without manual clean-up.

## Take data elsewhere (E)

- **E1** When I need to share or analyse outside the app, I want to export, as a spreadsheet file, the companies currently shown in a group (with the fields I've chosen), the qualification notes currently shown, and the full record of past clients (name, parent or subsidiary, parent's name, sector, counted or not), so that I can report or archive.

## Work anywhere, together (A)

- **A1** When colleagues change something, I want to see it appear without reloading, so that we never work from stale information.
- **A2** When I'm away from my desk, I want to use everything on my phone as well as on a large display, and install it like an app on my home space, so that I can check and update on the go.
- **A3** When I open the app with no connection, I want it to at least open rather than fail completely, so that I'm not met with only an error.
- **A4** When I move between areas, I want to get anywhere in one or two steps on both phone and large displays, so that switching jobs is quick.

## States to design

- **Nothing yet:** no tasks; no tasks of a given kind (internal, prospect, client); nothing on a selected day; nothing in a month; a person with no tasks; no flows; no companies in a group, or none matching search and filters; no qualification notes, or none matching search; no past clients, or none matching search; no counted companies for the sector breakdown; no other parent company to move a subsidiary to.
- **Loading:** tasks, flows, companies, qualification notes, past clients, external events (each loads on its own).
- **Saving:** notes saving as you go; adding or moving a past client in progress.
- **Failure:** couldn't save (past clients); couldn't create a follow-up task or task group; external events not set up or couldn't be fetched.
- **No connection:** the app opens but data may not load.
- **Read-only:** external events.
- **Live-synced:** every change by anyone appears for everyone.
- **Urgency:** task deadline within 3 days or missed; days since last action (fine, getting late, too long); company target date close or missed; company going cold (no contact for 14+ days).
- **Done:** finished tasks hidden by default; when shown, they look clearly finished.
- **Undated:** tasks without dates.
- **Not counted:** a parent company kept on record but excluded from totals.
- **Required missing:** a task without a description, a company without a name, a task group without a name or with a name already in use.
- **Confirming:** deleting a task, task group, company, choice option, own field, flow, qualification notes, past client or subsidiary.

## Roles and permissions

- Nobody signs in. Everyone who opens the app can see and change everything.
- Responsible persons, informed persons and flow-step roles are names attached to work, not accounts.

## Hard constraints

- Works on phones and large displays; installable as an app.
- Live shared data for everyone in the team.
- Spreadsheet export (comma-separated) for companies, qualification notes and past clients.
- External events come read-only from one shared outside scheduling account.
